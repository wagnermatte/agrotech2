Do CSV bruto ao número na tela.

{# ================= 1. O PROBLEMA ================= #}
01 · O problema

A máquina gera dados. Pouca gente consegue usá-los.

Tratores, plantadeiras, pulverizadores e colheitadeiras registram velocidade, rotação do motor, posição e o que estavam fazendo a cada segundo. Esses registros raramente chegam organizados a quem decide, e perguntas simples ficam sem resposta: quanto tempo a máquina trabalhou? Quanto ficou parada de motor ligado?

14%

dos alimentos produzidos no mundo se perdem entre a colheita e o varejo.

FAO, The State of Food and Agriculture 2019
2 sacas/ha

é a perda média estimada na colheita de soja no Brasil, o dobro do tolerável. Na safra 2004/05, cerca de 44 milhões de sacas.

Embrapa Soja, prevenção de perdas na colheita
80%

das perdas na colheita de soja vêm da plataforma de corte do maquinário, ou seja, de regulagem e operação da máquina.

53%

das máquinas cadastradas em três concessionárias tinham telemetria ativa em 2022. A outra metade não registrava nada. Quem tem o dado enxerga longe.

Santos, UFV, 2023, Telemetria na região central do Brasil
até 1,40

sacas/ha perdidas por operador sem treinamento, no Paraná, safra 2022/23. Operadores treinados perdem em média 1,06 sacas/ha. Quem tem informação perde menos.

Embrapa Soja, monitoramento de perdas 2022/23

E, na maioria das vezes, quando o dado existe, ele chega bagunçado e desestruturado.

Cada fabricante dá um nome para a mesma coluna. Estados vêm em código, números usam vírgula ou ponto, há linhas repetidas, fora de ordem e buracos sem registro. Antes de qualquer gráfico, alguém precisa arrumar isso e deixar claras as regras da conta. É isso que o AgroTech faz.

01De onde vêm os dados

Para testar sem um trator de verdade, o telemetriaCriar.py gera 168 horas de telemetria, uma linha por segundo. Das 7h às 18h a máquina repete um ciclo de 10 minutos: 7 trabalhando, 1 manobrando, 1 deslocando e 1 parada. Fora desse horário, fica parada com o motor desligado.

O random.seed(42) faz o arquivo sair sempre igual, assim os resultados podem ser conferidos. O projeto exige deixar claro quando um dado é simulado (regra RF10), por isso o aviso aparece no site.

{{ bloco("telemetriaCriar.py", codigos.gerador) }}

02O roteiro

processar_arquivo é a função que chama todas as outras, na ordem. Cada linha dela é um dos próximos passos.

Se algum passo encontra um problema, ele levanta um erro e o processamento para ali, sem gerar número errado.

{{ bloco("validarArquivo.py", codigos.processar_arquivo) }}

03Abrir o arquivo com segurança

ler_csv chama validar_arquivo para conferir se o arquivo existe, termina em .csv e não está vazio. Depois usa csv.DictReader, que transforma cada linha num dicionário com o nome da coluna como chave.

O encoding="utf-8-sig" remove um caractere invisível que o Excel coloca no começo do arquivo. Erros do sistema operacional viram um erro nosso, com mensagem em português.

{{ bloco("validarArquivo.py", codigos.ler_csv) }}

04Entender colunas de fontes diferentes

O dicionário mapaColunas diz que nomes cada informação pode ter. validar_colunas compara esses nomes com o cabeçalho, sem diferenciar maiúsculas e minúsculas, e devolve qual coluna corresponde a quê.

Tempo e estado são obrigatórios. Velocidade e RPM são opcionais: se faltarem, as outras análises continuam (regra RF01). Para aceitar um novo fabricante, basta acrescentar o nome da coluna dele na lista.

{{ bloco("validarArquivo.py", codigos.mapas, codigos.validar_colunas) }}
{# ---------- FASE 2: LIMPAR ---------- #}
{{ cabeca_fase(fases[1]) }}

05Transformar texto em horário

No CSV tudo é texto. validar_timestamps usa datetime.strptime para converter "2026-11-01 07:00:00" num horário de verdade, que permite fazer contas e ordenar.

Uma linha com horário inválido é descartada com continue, em vez de travar o programa. Se nenhuma linha sobrar, aí sim é erro.

{{ bloco("validarArquivo.py", codigos.validar_timestamps) }}

06Traduzir os estados

normalizar_estados tira espaços, passa para maiúsculas e procura o código no mapaEstados. Assim W, w e Working viram o mesmo estado.

O .get(..., estadoDesconhecido) garante que um código estranho vire “desconhecido” em vez de sumir. Ele aparece em vermelho no quadro, para ninguém ser enganado.

{{ bloco("validarArquivo.py", codigos.normalizar_estados) }}

07Ler números com vírgula ou ponto

converter_numero troca a vírgula por ponto antes de converter para float, porque planilhas brasileiras usam vírgula.

Quando o valor está vazio ou inválido, a função devolve None, nunca zero. Um zero inventado puxaria a média para baixo (regra RF07).

{{ bloco("validarArquivo.py", codigos.converter_numero) }}

08Tirar linhas repetidas

remover_duplicatas transforma cada registro numa tupla e guarda as que já viu num set. Se a mesma linha aparecer de novo, é ignorada.

O set foi escolhido porque verificar se um item está nele é praticamente instantâneo, mesmo com 600 mil linhas. Com uma lista, o programa ficaria muito mais lento.

{{ bloco("validarArquivo.py", codigos.remover_duplicatas) }}
{# ---------- FASE 3: MEDIR ---------- #}
{{ cabeca_fase(fases[2]) }}

09Medir o tempo entre registros

Depois de ordenar por horário (ordenar_registros), validar_intervalos calcula quantos segundos se passaram entre cada registro e o anterior. Esse é o tempo que a máquina ficou naquele estado.

Só valem intervalos maiores que 0 e de até dtMaximoSeg ({{ constantes.dtMaximoSeg }} s). Se o sensor ficou duas horas sem enviar nada, esse buraco não vira trabalho (regra RF04).

{{ bloco("validarArquivo.py", codigos.constantes, codigos.validar_intervalos) }}

10Recusar dados de menos

validar_quantidade_intervalos exige pelo menos {{ constantes.minimoIntervalos }} intervalos válidos, cerca de um minuto de operação.

Com menos que isso, qualquer percentual seria enganoso. O projeto pede que o sistema não produza resultado com registros insuficientes.

{{ bloco("validarArquivo.py", codigos.validar_quantidade_intervalos) }}

11Somar o tempo de cada estado

calcular_permanencia_estados começa com zero segundos para cada estado e vai somando a duração de cada intervalo no estado certo. No fim, divide pelo total para obter o percentual.

A utilização produtiva é o percentual de “Trabalhando” e a taxa de parada é o de “Ocioso”, conforme a seção 4.1 do projeto (calcular_indicadores).

{{ bloco("validarArquivo.py", codigos.calcular_permanencia_estados) }}

12RPM e velocidade

calcular_metricas usa calcular_extremos para achar mínimo, média e máximo, ignorando valores vazios.

A velocidade média considera só os estados em operação (Trabalhando, Manobrando, Deslocando). Se as horas paradas entrassem na conta, a média cairia e não diria nada sobre como a máquina anda quando trabalha.

{{ bloco("validarArquivo.py", codigos.calcular_metricas) }}

13Erros com nome

Todos os erros previstos herdam de AgroTechError. A tela só precisa de um try/except AgroTechError para mostrar a mensagem certa, sem esconder erros de programação inesperados.

Na página de gerar análise, coloque o início igual ao fim: a mensagem que aparece vem de DadosInsuficientesError.

Testar o erro →

14Analisar só um período

Para a página de análise, processar_periodo reaproveita os mesmos passos e acrescenta filtrar_por_periodo, que mantém só os registros entre o início e o fim escolhidos.

Como as regras são as mesmas, a análise de um dia segue exatamente o mesmo cálculo da semana inteira.

{{ bloco("validarArquivo.py", codigos.processar_periodo) }}

15Desenhar a semana

calcular_linha_do_tempo agrupa os intervalos por hora e escolhe o estado com mais segundos naquela hora. É o que pinta o quadro da página inicial.

max(tempos, key=tempos.get) devolve a chave do dicionário com o maior valor, ou seja, o estado predominante. Os segundos de cada estado também ficam guardados, e aparecem ao passar o mouse no quadro.

16Guardar para abrir depois

salvar_analise grava cada análise como um arquivo .json na pasta {{ pastaAnalises }}/. Não há banco de dados no MVP: o JSON é texto legível, e o Python lê e escreve esse formato com a biblioteca padrão.

Onde fica
Na pasta {{ pastaAnalises }}/, no disco do computador que roda o site. Um arquivo por análise{% if exemplo %}, hoje {{ exemplo.quantidade }} {{ 'arquivo' if exemplo.quantidade == 1 else 'arquivos' }}{% endif %}.
Nome do arquivo
A data e a hora da criação, no formato AAAAMMDD-HHMMSS.json. Esse nome também é o endereço da análise: /analise/AAAAMMDD-HHMMSS.
O que vai dentro
Só o resultado: nome, período, arquivo de origem, data de criação, indicadores, tempo em cada estado, RPM, velocidade, a linha do tempo hora a hora e o tempo de motor desligado. As 600 mil linhas brutas não são copiadas, por isso cada arquivo tem poucos KB{% if exemplo %} (o mais recente tem {{ numero(exemplo.tamanho / 1024) }} KB){% endif %}.
Como a lista é montada
listar_analises lê a pasta e ordena os nomes ao contrário. Como o nome é a data e a hora, a análise mais nova aparece primeiro, sem precisar de outro campo de ordem.
Proteção ao abrir
carregar_analise só aceita letras, números e hífen no identificador. Um identificador com ponto ou barra, como ../app, é recusado antes de qualquer leitura, e por isso ninguém abre arquivos fora da pasta pelo endereço.
E o PDF?
Não fica salvo. A cada clique em "Baixar PDF", gerar_pdf monta o documento na hora a partir do JSON, com a biblioteca fpdf2. Assim existe uma única cópia dos dados.
Versões antigas
Análises salvas antes da versão atual não têm os minutos por hora nem o motor desligado. Elas continuam abrindo: a página só esconde o que falta.
Limites
A pasta fica fora do Git (.gitignore), não é compartilhada entre computadores e não tem controle de quem vê o quê. Em hospedagens sem disco permanente, como o plano gratuito do Render, ela é apagada a cada deploy. Na V1, o plano é trocar por SQLite ou PostgreSQL.

{# ================= 4. RESUMO TÉCNICO ================= #}
05 · Resumo técnico

Quatro etapas no sistema: do CSV aos insights.

  1. 1 → EntradaRecebe o CSV e confere se dá para ler.ler_csv · validar_arquivo
  2. 2 → ProcessamentoValida, limpa, mede intervalos e calcula indicadores.validarArquivo.py
  3. 3 → DadosProcessa em memória e salva cada análise em JSON.analises/*.json
  4. 4 → ApresentaçãoJanela de computador e site local.interface.py · app.py · templates/

Tecnologias

  • Python 3, com csv, datetime, math, os e json da biblioteca padrão
  • Flask, para o site local
  • fpdf2, para gerar o PDF
  • tkinter, para a janela de computador
  • HTML, CSS e JavaScript simples, sem framework

O documento do projeto cita Pandas e Streamlit. No MVP preferimos a biblioteca padrão para cada passo do cálculo ficar visível no código.

Como rodar

$ python3 -m venv .venv
$ .venv/bin/pip install -r requirements.txt
$ .venv/bin/python app.py

Depois abra http://127.0.0.1:5001 no navegador.

Limites conhecidos

  • Os dados da semana são simulados.
  • Não existe estado “Desligado”: horas de motor desligado entram como Ocioso e puxam o RPM médio para baixo.
  • O arquivo de 168 horas tem cerca de 600 mil linhas e leva alguns segundos para processar.
  • Uma máquina e um arquivo por vez.
