{# ================= 1. O PROBLEMA ================= #}

A máquina gera dados. Pouca gente consegue usá-los.

Tratores, plantadeiras, pulverizadores e colheitadeiras registram velocidade, rotação do motor, posição e o que estavam fazendo a cada segundo. Esses registros raramente chegam organizados a quem decide, e perguntas simples ficam sem resposta: quanto tempo a máquina trabalhou? Quanto ficou parada de motor ligado? A operação desta semana foi melhor que a da anterior?

E quando o dado existe, ele chega bagunçado

Cada fabricante dá um nome diferente para a mesma coluna (timestamps ou timestamp, STATE ou operational_state). Estados vêm em código (W, T, I). Números usam vírgula ou ponto. Há linhas repetidas, horários fora de ordem e buracos de minutos sem registro. Se a conta for feita em cima disso sem cuidado, um buraco de duas horas vira "duas horas trabalhando".

Antes de qualquer gráfico, alguém precisa arrumar os dados e deixar claras as regras da conta. É isso que o AgroTech faz.

O que o AgroTech faz hoje

Este é o MVP. Faz pouca coisa, mas cada número na tela vem de uma regra escrita no código, e você pode conferir todas mais abaixo.

  • Lê o CSV de telemetriaAceita colunas com nomes diferentes de fontes diferentes e identifica tempo, estado, velocidade e RPM.
  • Confere o arquivoVerifica se ele existe, se é .csv, se não está vazio, se tem cabeçalho e se tem as colunas obrigatórias.
  • Limpa os dadosConverte horários, traduz estados (W vira Trabalhando), aceita vírgula decimal, remove linhas duplicadas e ordena por horário.
  • Mede o tempo com honestidadeSó conta intervalos de até {{ constantes.dtMaximoSeg }} segundos entre um registro e o próximo. Buracos maiores não viram tempo de trabalho. Exige pelo menos {{ constantes.minimoIntervalos }} intervalos válidos.
  • Calcula indicadoresPercentual de tempo em cada estado, utilização produtiva, taxa de parada, RPM médio e máximo, velocidade média em operação e máxima.
  • Analisa um período e guardaVocê escolhe o intervalo de datas, a análise fica salva e pode ser aberta de novo ou baixada em PDF.
  • Duas interfacesUma janela de computador (interface.py, com tkinter) e este site local (app.py, com Flask).

{# ================= 3. O CÓDIGO, PASSO A PASSO ================= #}

Como o código faz isso

Toda a lógica fica em validarArquivo.py. Os trechos abaixo são lidos direto desse arquivo quando a página abre, então o que aparece aqui é exatamente o código que está rodando.

A ordem segue o caminho de um registro: do arquivo bruto até o número na tela.

  1. De onde vêm os dados

    Para testar sem um trator de verdade, o telemetriaCriar.py gera 168 horas de telemetria, uma linha por segundo. Das 7h às 18h a máquina repete um ciclo de 10 minutos: 7 trabalhando, 1 manobrando, 1 deslocando e 1 parada. Fora desse horário, fica parada com o motor desligado.

    O random.seed(42) faz o arquivo sair sempre igual, assim os resultados podem ser conferidos. O projeto exige deixar claro quando um dado é simulado (regra RF10), por isso avisamos no topo da página.

    {{ codigos.gerador }}

  2. O roteiro

    processar_arquivo é a função que chama todas as outras, na ordem. Cada linha dela é um dos próximos passos. Se algum passo encontra um problema, ele levanta um erro e o processamento para ali, sem gerar número errado.

    {{ codigos.processar_arquivo }}

  3. Abrir o arquivo com segurança

    ler_csv chama validar_arquivo para conferir se o arquivo existe, termina em .csv e não está vazio. Depois usa csv.DictReader, que transforma cada linha num dicionário com o nome da coluna como chave.

    O encoding="utf-8-sig" remove um caractere invisível que o Excel coloca no começo do arquivo. Erros do sistema operacional viram um erro nosso, com mensagem em português.

    {{ codigos.ler_csv }}

  4. Entender colunas de fontes diferentes

    O dicionário mapaColunas diz que nomes cada informação pode ter. validar_colunas compara esses nomes com o cabeçalho do arquivo, sem diferenciar maiúsculas e minúsculas, e devolve qual coluna corresponde a quê.

    Tempo e estado são obrigatórios. Velocidade e RPM são opcionais: se faltarem, as outras análises continuam funcionando (regra RF01). Para aceitar um novo fabricante, basta acrescentar o nome da coluna dele na lista.

    {{ codigos.mapas }}
    {{ codigos.validar_colunas }}

  5. Transformar texto em horário

    No CSV tudo é texto. validar_timestamps usa datetime.strptime para converter "2026-11-01 07:00:00" num horário de verdade, que permite fazer contas e ordenar.

    Uma linha com horário inválido é descartada com continue, em vez de travar o programa. Se nenhuma linha sobrar, aí sim é erro.

    {{ codigos.validar_timestamps }}

  6. Traduzir os estados

    normalizar_estados tira espaços, passa para maiúsculas e procura o código no mapaEstados. Assim W, w e Working viram o mesmo estado.

    O .get(..., estadoDesconhecido) garante que um código estranho vire "desconhecido" em vez de sumir. Ele aparece no resultado para ninguém ser enganado.

    {{ codigos.normalizar_estados }}

  7. Ler números com vírgula ou ponto

    converter_numero troca a vírgula por ponto antes de converter para float, porque planilhas brasileiras usam vírgula.

    Quando o valor está vazio ou inválido, a função devolve None, nunca zero. Um zero inventado puxaria a média para baixo. O projeto exige mostrar "indisponível" em vez de inventar um número (regra RF07).

    {{ codigos.converter_numero }}

  8. Tirar linhas repetidas

    remover_duplicatas transforma cada registro numa tupla e guarda as que já viu num set. Se a mesma linha aparecer de novo, é ignorada.

    O set foi escolhido porque verificar se um item está nele é praticamente instantâneo, mesmo com 600 mil linhas. Com uma lista, o programa ficaria muito mais lento.

    {{ codigos.remover_duplicatas }}

  9. Medir o tempo entre registros

    Depois de ordenar por horário (ordenar_registros), validar_intervalos calcula quantos segundos se passaram entre cada registro e o anterior. Esse é o tempo que a máquina ficou naquele estado.

    Só valem intervalos maiores que 0 e de até dtMaximoSeg ({{ constantes.dtMaximoSeg }} s). Se o sensor ficou duas horas sem enviar nada, esse buraco não é contado como trabalho (regra RF04).

    {{ codigos.constantes }}
    {{ codigos.validar_intervalos }}

  10. Recusar dados de menos

    validar_quantidade_intervalos exige pelo menos {{ constantes.minimoIntervalos }} intervalos válidos, cerca de um minuto de operação.

    Com menos que isso, qualquer percentual seria enganoso. O projeto pede que o sistema não produza resultado com registros insuficientes.

    {{ codigos.validar_quantidade_intervalos }}

  11. Somar o tempo de cada estado

    calcular_permanencia_estados começa com zero segundos para cada estado e vai somando a duração de cada intervalo no estado certo. No fim, divide pelo total para obter o percentual.

    A utilização produtiva é o percentual de "Trabalhando" e a taxa de parada é o de "Ocioso", conforme a seção 4.1 do projeto (calcular_indicadores).

    {{ codigos.calcular_permanencia_estados }}

  12. RPM e velocidade

    calcular_metricas usa calcular_extremos para achar mínimo, média e máximo, ignorando valores vazios.

    A velocidade média considera só os estados em operação (Trabalhando, Manobrando, Deslocando). Se as horas parada entrassem na conta, a média cairia e não diria nada sobre como a máquina anda quando trabalha.

    {{ codigos.calcular_metricas }}

  13. Erros com nome

    Todos os erros previstos herdam de AgroTechError. A tela só precisa de um try/except AgroTechError para mostrar a mensagem certa, sem esconder erros de programação inesperados.

    Na página de gerar análise, tente colocar o início igual ao fim: a mensagem que aparece vem de DadosInsuficientesError.

    {{ codigos.erros }}

  14. Analisar só um período

    Para a página de análise, processar_periodo reaproveita os mesmos passos e acrescenta filtrar_por_periodo, que mantém só os registros entre o início e o fim escolhidos.

    Como as regras são as mesmas, a análise de um dia segue exatamente o mesmo cálculo da semana inteira.

    {{ codigos.processar_periodo }}

  15. Desenhar a semana

    calcular_linha_do_tempo agrupa os intervalos por hora e escolhe o estado com mais segundos naquela hora. É o que pinta o quadro do topo desta página.

    max(tempos, key=tempos.get) devolve a chave do dicionário com o maior valor, ou seja, o estado predominante.

    {{ codigos.calcular_linha_do_tempo }}

  16. Guardar para abrir depois

    salvar_analise grava o resultado num arquivo .json dentro da pasta analises. O nome do arquivo é a data e a hora da criação.

    Ainda não há banco de dados no MVP, e o JSON resolve: é texto legível, o Python lê e escreve com a biblioteca padrão, e o PDF é gerado a partir dele quando você pede (gerar_pdf).

    {{ codigos.salvar_analise }}
{# ================= 4. FECHAMENTO TÉCNICO ================= #}

Resumo técnico

O sistema segue as quatro camadas do projeto. Cada uma tem um arquivo responsável.

EntradaRecebe o CSV e confere se dá para ler.
ler_csv validar_arquivo
ProcessamentoValida, limpa, mede intervalos e calcula indicadores.
validarArquivo.py
DadosProcessa em memória e salva cada análise em JSON.
analises/*.json
ApresentaçãoJanela de computador e site local.
interface.py app.py templates/

Tecnologias

  • Python 3, com csv, datetime, math, os e json da biblioteca padrão
  • Flask, para o site local
  • fpdf2, para gerar o PDF
  • tkinter, para a janela de computador
  • HTML e CSS simples, sem framework

O documento do projeto cita Pandas e Streamlit. No MVP preferimos a biblioteca padrão para cada passo do cálculo ficar visível no código.

Como rodar

python3.14 -m venv .venv .venv/bin/pip install -r requirements.txt .venv/bin/python app.py

Depois abra http://127.0.0.1:5001 no navegador.

Limites conhecidos

  • Os dados da semana são simulados.
  • O RPM médio inclui as horas de motor desligado (RPM 0), o que puxa a média para baixo.
  • O arquivo de 168 horas tem cerca de 600 mil linhas e leva alguns segundos para processar.
  • Uma máquina e um arquivo por vez.
